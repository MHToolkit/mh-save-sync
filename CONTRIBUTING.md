# Contributing

1. Open or link an issue describing area, platform, risk and acceptance proof.
2. Create a branch; do not push feature implementations directly to `main`.
3. Add or update ADRs for protocol, data-format, security, storage,
   compatibility or performance-budget changes.
4. Use synthetic fixtures only.
5. Run formatting, lint, tests, secret scanning and `git diff --check`.
6. Include reproducible evidence in the pull request.

Changes touching crypto, snapshot formats, adapters, deployment or workflows
require review from the corresponding CODEOWNERS.
